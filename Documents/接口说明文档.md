## 2. 通用约定

### 2.1 Base URL

```
http://localhost:8080
```

### 2.2 统一响应格式

所有接口（除 SSE 流式接口外）均返回统一结构：

```json
{
  "code": 200,
  "msg": "success",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | 业务状态码，`200` 成功 |
| `msg` | string | 提示信息 |
| `data` | object \| null | 业务数据 |

### 2.3 状态码

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / token 无效或过期 |
| 500 | 服务器内部错误 |

> HTTP 状态码与业务 `code` 通常一致（401 时 HTTP 也返回 401）。

### 2.4 时间格式

- 日期：`yyyy-MM-dd`（如 `2026-07-31`）
- 日期时间：`yyyy-MM-dd'T'HH:mm:ss`（如 `2026-07-31T14:57:02`）

## 3. 鉴权说明

系统有两种凭证：**用户会话 Token** 和 **AI 集成密钥**。

### 3.1 用户会话 Token（绝大多数接口）

- 通过 `POST /api/user/login` 获取。
- 请求头传值：`Authorization: <token>`（**不加 `Bearer` 前缀**，直接放原始 token）。
- Token 存储在 **Redis**（key=token, value=userId），默认有效期 **72 小时**（配置项 `token.expiry`），过期由 TTL 自动清理。
- 过期后会话不存在，返回 `401 token已过期，请重新登录`。

**Postman 测试方法**：Authorization 选择 `No Auth`，手动在 Headers 中添加：

```
Authorization: <登录返回的token>
```

### 3.2 AI 集成密钥（仅 `/api/ai/**`）

- Dify Agent 等系统调用 AI 接口时使用固定密钥：`teamsync-ai-key-2026`。
- 请求头传值：`Authorization: teamsync-ai-key-2026`。
- **作用域仅限 `/api/ai/**`**；其他路径（如 `/api/user/me`、`/api/schedule/**`）不接受该密钥。
- AI 密钥调用时**无登录会话**，接口中用户身份一律通过显式 `userId` 参数指定。

### 3.3 鉴权矩阵

| 接口范围 | 用户 Token | AI 密钥 | 无需鉴权 |
|---|---|---|---|
| `/api/user/login`、`/api/user/register` | — | — | ✅ |
| `/api/ai/**` | ✅ | ✅ | ❌ |
| 其余 `/api/**` | ✅ | ❌ | ❌ |

### 3.4 登录流程

1. 前端调用 `POST /api/user/login`（用户名不存在时**自动注册**为 `MEMBER` 角色）。
2. 后端返回 `token`，前端存入 `localStorage`。
3. 后续请求由 axios 拦截器自动附加 `Authorization` 头。

## 4. 接口明细

### 4.1 用户模块 `/api/user`

---

#### 4.1.1 登录（自动注册）

`POST /api/user/login` ｜ **无需鉴权**

**请求体：**

```json
{
  "username": "张三",
  "password": "123456"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `username` | string | 是 | 用户名；不存在则自动注册 |
| `password` | string | 否 | 密码；不填则忽略（首次注册存储） |

**响应：**

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "c3e5a1f9...",
    "userId": 2,
    "username": "张三",
    "role": "MEMBER",
    "avatar": null
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `token` | string | 会话令牌（72h 有效），后续请求放入 `Authorization` |
| `userId` | number | 用户ID |
| `username` | string | 用户名 |
| `role` | string | 角色（`MEMBER` / 管理员） |
| `avatar` | string? | 头像 |

> 密码错误时返回 `code 500, msg 密码错误`。

---

#### 4.1.2 注册

`POST /api/user/register` ｜ **无需鉴权**

与登录接口逻辑一致（用户名不存在时注册），请求/响应格式同上。

---

#### 4.1.3 退出登录

`POST /api/user/logout` ｜ **需要 Token**

无请求体。后端从 `Authorization` 头读取 token 并**从 Redis 删除**，会话立即失效。

**响应：** `{"code":200,"msg":"success","data":null}`

---

#### 4.1.4 获取当前用户信息

`GET /api/user/info` ｜ **需要 Token**

返回当前登录用户的完整 `SysUser` 对象。

**响应 data：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 用户ID |
| `username` | string | 用户名 |
| `password` | string | 密码（明文，仅内部使用） |
| `avatar` | string? | 头像 |
| `role` | string | 角色 |
| `createdAt` | datetime | 创建时间 |

---

#### 4.1.5 获取当前用户 ID

`GET /api/user/me` ｜ **需要 Token（不接受 AI 密钥）**

**响应 data：**

```json
{
  "userId": 2,
  "username": "张三",
  "role": "MEMBER"
}
```

> 前端判断登录态、获取用户 ID 时使用此接口。

### 4.3 成果模块 `/api/achievement`

> 需要 Token。提交成果后异步触发 AI 评估（写 `ai_result` 表）。

---

#### 4.3.1 提交成果（复合：文本+文件）

`POST /api/achievement/upload` ｜ **需要 Token，仅本人** ｜ `Content-Type: multipart/form-data`

**表单字段：**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `scheduleId` | number | 是 | 所属日程ID（校验归属） |
| `items` | string | 否 | JSON 数组字符串，描述各条成果项 |
| `files` | file[] | 否 | 上传的文件，通过 `item.fileIndex` 关联 |

**`items` JSON 格式（每条项）：**

```json
[
  {
    "contentType": "TEXT",          // "TEXT" 文本 或 "FILE" 文件
    "content": "今日完成高数第三章",  // TEXT 时的内容
    "fileName": "笔记.jpg",          // FILE 时的文件名
    "fileIndex": 0,                 // 关联 files 数组下标
    "existingFileUrl": null         // 二次提交时保留旧文件可传此值
  }
]
```

**行为说明：**

- 该日程**首次**提交时：创建成果记录，并把日程状态置为 `2`（已完成）。
- **重复**提交时：更新已有成果、清空并重建明细，日程状态不变。
- 提交完成后异步调用 AI 评估（DeepSeek），生成 `diligenceScore` / `aiComment` / `aiSummary`。

**响应 data：** `Achievement` 实体（`id`、`scheduleId`、`createdAt`）。

---

#### 4.3.2 查询日程成果

`GET /api/achievement/bySchedule/{scheduleId}` ｜ **需要 Token**

**路径参数：** `scheduleId`

**响应 data：** `Achievement`（最新一条），无则 `data: null`。

### 4.6 AI 助手（Dify 会话）`/api/ai-assistant`

> 需要 Token。所有 Dify 调用以当前登录用户的 userId 作为 `user` 参数，**会话数据按用户隔离**。

---

#### 4.6.1 发送消息（SSE 流式）

`POST /api/ai-assistant/chat` ｜ **需要 Token** ｜ 响应 `Content-Type: text/event-stream`

**请求体：**

```json
{
  "query": "帮我分析今天的学习情况",
  "conversation_id": ""
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query` | string | 是 | 用户消息 |
| `conversation_id` | string | 否 | 会话ID；空串表示新建会话 |

**响应：** SSE 流，逐行转发 Dify 事件，格式为 `data: <json>` 行：

```text
data: {"event":"message","conversation_id":"...","answer":"增量文本"}

data: {"event":"message_end","conversation_id":"...","answer":"完整回答"}

data: {"event":"error","code":...,"msg":"错误信息"}
```

**关键事件：** `message`（增量）、`message_end`（结束）、`error`（出错）。

> 前端使用 `XMLHttpRequest` 的 `onprogress` 增量解析；`message_end` 后主动断开。

## 5. 数据字典

### 5.1 `sys_user` — 用户

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 用户ID |
| `username` | VARCHAR | 用户名 |
| `password` | VARCHAR | 密码（明文） |
| `avatar` | VARCHAR? | 头像 |
| `role` | VARCHAR | `MEMBER` / 管理员 |
| `created_at` | DATETIME | 创建时间 |

### 5.2 会话（存 Redis，无 MySQL 表）

会话存 Redis：key = 登录返回的 token（UUID），value = userId，TTL = `token.expiry`（默认 72h）。登出时从 Redis 删除该 key。

| token（VARCHAR, UUID） | userId | 过期由 Redis TTL 兜底 |

## 6. Dify Agent 对接说明

### 6.1 内网地址映射

Dify（Docker）无法直接访问宿主机 `localhost`，必须使用：

```
http://host.docker.internal:8080
```

> 宿主机需在 Dify `.env` 中配置 `SSRF_PROXY_ALLOW_PRIVATE_DOMAINS=host.docker.internal`，否则会被 Squid 代理的 SSRF 防护拦截。

### 6.2 Agent 工具与后端接口映射

对应 `Agent/学习助手 .yml` 中的工具定义：

| Dify 工具 | 调用的后端接口 | 鉴权 |
|---|---|---|
| `save_study_schedule`（保存学习日程） | `POST /api/ai/schedule/generate`（或前端日程接口） | AI 密钥 |
| `save_study_result`（保存学习成果） | 前端成果接口 `POST /api/achievement/upload` | 用户 Token |
| `query_study_history`（查询学习历史） | `GET /api/ai/recent-records` | AI 密钥 |
| `generate_next_schedule`（生成日程建议） | `POST /api/ai/schedule/generate` | AI 密钥 |
| `execute_SQL`（通用数据操作，预留） | — | — |

### 6.3 密钥使用

- 调用 `/api/ai/**` 工具时，请求头填 `Authorization: teamsync-ai-key-2026`。
- `userId` 建议用 Dify 系统变量 `{{#sys.user_id#}}` 动态获取当前聊天用户，**不要写死**。
- AI 密钥为共享固定密钥，请勿提交到前端代码或公开仓库。

### 6.4 建议工作流 HTTP 节点示例

```
GET http://host.docker.internal:8080/api/ai/recent-records
Params: userId = {{#sys.user_id#}} , days = 10
Headers: Authorization = teamsync-ai-key-2026
```

```
POST http://host.docker.internal:8080/api/ai/schedule/generate
Headers: Authorization = teamsync-ai-key-2026 , Content-Type = application/json
Body:
{
  "userId": "{{#sys.user_id#}}",
  "analysisSummary": "{{analysisSummary}}",
  "weakPoints": "{{weakPoints}}",
  "recentTrends": "{{recentTrends}}"
}
```
